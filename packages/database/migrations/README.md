# Database Migrations

The ordered Supabase migration bundle is owned by `@reservation-platform/database`.

`supabase/migration-index.json` is generated by
`scripts/generate-database-migration-index.mjs`. It records the exact core
apply order, optional AI retrieval migrations, development seed inputs,
sha256 checksums, and byte sizes using repo-relative paths. Treat it as a
future runner input and drift guard, not as evidence that any database has
applied these files.

Some migration files are now curated runnable package assets with explicit
source provenance, including the core reservation schema, RLS policies, atomic
reservation RPC, core security hardening, and durable idempotency SQL. The
security hardening migration intentionally carries only package-owned function
search-path and RPC privilege hardening from the mixed source file; seed,
backfill, content/reporting, AI, and storage sections remain outside the core
bundle. Remaining placeholders or compatibility assets should stay clearly
linked to their source SQL until they are curated.

Before release, implementation work still needs to apply the bundle to an empty
disposable database, apply relevant development seeds, and prove RLS, tenant
isolation, live atomic reservation behavior, and durable idempotency against the
migrated schema.
