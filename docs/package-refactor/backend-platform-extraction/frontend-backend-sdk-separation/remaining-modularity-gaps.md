# Remaining Modularity Gaps

This index answers whether the known remaining modularity work is captured in
the phase docs. It does not replace the phase plans; it points each gap to the
phase that owns it so subagents can work from one phase file without losing the
overall outcome.

The focused execution plan for proving hard frontend/backend separation lives in
[Frontend and Backend Hard Separation Plan](frontend-backend-hard-separation-plan/README.md).
Use it when the question is whether the backend platform, SDK, and frontend are
actually separable products rather than modular packages inside this monorepo.

## Subagent Handoff Rule

When assigning a subagent a remaining gap, give it this index plus the owning
phase result file. The subagent should update both files when it completes or
changes the status of a gap.

If a later phase discovers that an earlier phase needs a new contract or
backend capability, update the earlier phase result first, then update this
index and the downstream phase result. This keeps the phase sequence stable and
prevents a later proof from silently depending on undocumented work.
